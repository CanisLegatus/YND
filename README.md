# Yandex Disk Backup

Локальная программа резервного копирования фотографий и видео с Яндекс Диска.
Обход каталогов, скачивание оригиналов по отдельности, возобновление после
обрыва и проверяемый отчёт о полноте копии — без единого ZIP-архива.

Принципы, заложенные в код:

* только официальный REST API Яндекс Диска и официальный OAuth Яндекс ID;
* пароль пользователя не используется и не запрашивается;
* программа **никогда** не удаляет, не перемещает и не изменяет данные в облаке;
* токен не попадает в код, конфиг, логи и вывод на экран;
* незавершённый файл никогда не выглядит как сохранённый;
* отчёт не имеет права сказать «копия полна», если есть неразрешённые ошибки.

## 1. Установка

```bash
cd yandex-disk-backup
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

Python 3.9+ и один сторонний пакет — `requests`.

## 2. Настройка приложения Яндекса (один раз)

<https://oauth.yandex.ru/client/new> → платформа **«Веб-сервисы»** →
доступы: **только** «Чтение всего Диска» и «Информация о Диске».
Права на запись и удаление включать не нужно. Скопируйте **ClientID**
(секретный ключ не требуется — почему, написано в `docs/STAGE_A.md`).

## 3. Первый запуск

```bash
python main.py --setup     # внести ClientID, выбрать каталог копии
python main.py             # меню
```

| Ключ | Что делает |
|---|---|
| `python main.py` | меню |
| `python main.py --backup` | полный цикл без вопросов: обход → загрузка → отчёт |
| `python main.py --dry-run` | спланировать загрузку, ничего не скачивая |
| `python main.py --only-download` | скачать по существующему манифесту |
| `python main.py --check` | проверить OAuth и API, выйти |
| `python main.py --data-dir D:\ydb` | другой каталог данных |

### Меню

```
[1] Авторизоваться                [8] Отчёт о полноте резервной копии
[2] Проверить OAuth                [9] Сравнить с предыдущим манифестом
[3] Сведения о диске              [A] Все дела (обход + скачивание + отчёт)
[4] Обойти Диск и сохранить манифест  [B] Пробный запуск загрузки
[5] Показать статистику манифеста [C] Проверить свободное место
[6] Скачать файлы                 [D] Настройки и параметры
[7] Полный цикл                   [Q] Выйти и удалить локальный токен
```

## 4. Как это работает

```
обход диска  ──►  manifest.json   что есть в облаке (с метаданными)
                     │
                     ▼
                state.db        состояние каждого файла
                     │
                     ▼
                загрузка        временный .part → проверка → os.replace
                     │
                     ▼
                report.md/json   полнота, ошибки, пропуски, сверка
```

* **Обход** идёт в ширину, постранично (`limit`/`offset`), с прогрессом.
  Одна недоступная папка не роняет обход, но манифест честно помечается
  `incomplete`, и отчёт об этом говорит.
* **Манифест** пишется атомарно: временный файл рядом + `os.replace`.
  Прерванная запись не может оставить битый манифест.
* **Загрузка** — отдельными файлами по временным ссылкам из API. Сначала
  `.part`, потом проверка размера и контрольной суммы, и только потом файл
  занимает своё настоящее имя.
* **Возобновление** — состояние каждого файла в SQLite. После перезапуска
  программа не перекачивает проверенное и не считает прерванное сохранённым.
* **Отчёт** показывает, что полно, что нет, и почему.

Подробное обоснование решений — в `docs/PART2.md`, об OAuth — в
`docs/STAGE_A.md`.

## 5. Где что лежит

По умолчанию `%LOCALAPPDATA%\YandexDiskBackup\`:

| Файл | Содержимое |
|---|---|
| `config.json` | ClientID и параметры. **Без секретов.** |
| `token.json` | OAuth-токен, права доступа ограничены. В `.gitignore` |
| `manifest.json` | снимок облака: файлы, папки, метаданные |
| `manifest.prev.json` | предыдущий снимок для сверки |
| `state.db` | состояние каждого файла (SQLite) |
| `report.md` / `report.json` | отчёт о полноте |
| `backup.log` | журнал, секреты замаскированы |

Сами файлы копии — в каталоге, указанном при настройке (по умолчанию
`%USERPROFILE%\YandexDiskBackup`).

## 6. Проверка перед боевой загрузкой

```bash
python tests/run_tests.py       # 84 проверки логики, без сети
python tests/run_workflow.py    # 39 сквозных проверок, сеть подменена
```

Оба прогона работают офлайн и не трогают ваш реальный диск. Первый
проверяет пагинацию, коллизии имён, состояния, проверку хешей и обработку
ошибок; второй — весь цикл целиком, включая обрыв и порчу файла.

## 7. Критерии приёмки

| # | Проверка | Ожидаемый результат |
|---|---|---|
| 1 | `python main.py --dry-run` | План загрузки, ни одного скачанного байта |
| 2 | Пункт `4` | «Статус: полный обход», манифест создан |
| 3 | Пункт `5` | Счётчики совпадают с тем, что видно в Диске |
| 4 | Пункт `6` на маленькой папке | Файлы появились, структура совпала, размеры верны |
| 5 | Сравнить байты одного файла с оригиналом | Совпадение (двойной клик → свойства → хеш) |
| 6 | Пункт `A` на полном объёме | Отчёт: `Статус: Резервная копия полностью проверена` |
| 7 | `Ctrl+C` в середине, затем `python main.py` | Продолжение с места обрыва, дубликатов нет |
| 8 | Удалить файл из копии, запустить снова | Файл восстановлен, отчёт снова «полная копия» |
| 9 | Порча файла в копии, запуск | Файл перекачан, отчёт не врёт |
| 10 | Закрыть интернет на середине | Понятная ошибка, копия помечена неполной |
| 11 | `grep -i "y0_" backup.log report.md manifest.json` | Ничего; в логе только `***REDACTED***` |
| 12 | Пункт `C` до большой загрузки | Запас места достаточный |

Пункт 6 — единственный критерий, при котором **нельзя** соглашаться на
«примерно полную копию»: если статус не «полностью проверена», в отчёте
будут перечислены конкретные непроведённые дела.

## 8. Полезные настройки (пункт `D`)

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `concurrency` | 4 | одновременных загрузок. Больше — не всегда быстрее |
| `conflict_strategy` | `keep` | что делать с уже существующим локальным файлом |
| `allow_range_resume` | выкл | докачка через HTTP Range; см. `docs/PART2.md` §5 |
| `page_size` | 200 | размер страницы листинга |
| `min_request_interval` | 0.25 с | минимальный интервал между запросами к API |
| `max_attempts_per_file` | 3 | попыток на один файл |
| `free_space_margin` | 2 ГиБ | не начинать загрузку без такого запаса |

Прямые правки — в `%LOCALAPPDATA%\YandexDiskBackup\config.json`.

## 9. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| «токен отклонён (401)» | Пункт `1` — авторизоваться заново |
| «недостаточно прав (403)» | Проверить галочки доступов в настройках приложения |
| «превышен лимит запросов (429)» | Подождать; программа повторит сама, см. `docs/STAGE_A.md` §7 |
| Копия помечена неполной | Открыть `report.md`: там перечислены конкретные пропуски |
| `Копия полностью проверена` есть, а файла нет | Файл был удалён после проверки; пункт `8` это не покажет — смотрите `state.db` |

## 10. Отзыв доступа

Пункт `Q` в меню удаляет локальный токен и отзывает доступ на стороне
Яндекса. Вручную — <https://id.yandex.ru/personal/data-access>.
